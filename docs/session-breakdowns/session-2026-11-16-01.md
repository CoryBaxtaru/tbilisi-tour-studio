# Session Breakdown — 2026-11-16-01

## Objective
The founder asked for two things:
- a complete review of the website and the code, to see what can be done better;
- a way to turn Instagram DMs into bookings: paste the DM in "Nieuwe boeking" and have the form filled in, or another way to automate it.

## Completed
- **Message reader** (`src/domain/dmBooking.ts`, 11 tests): plain pattern matching, Dutch and English, no service and no cost.
  - Day: "21 november", "Nov 21st", "21-11", "morgen", "zaterdag", "next week Saturday"; a day without a year is the next one to come.
  - Time: "10:30", "10u30", "half 3", "at 4", "3pm", "om 8 uur 's avonds"; a bare hour from 1 to 7 counts as the afternoon.
  - Party: "met z'n zessen", "2 adults and 1 child", "6 personen, waarvan 2 kinderen", "a group of eight", "ik en mijn vrouw".
  - Name (introduction, sign-off or "Naam:"), contact (@name, e-mail, phone), private group, wishes (diet, mobility, interests) and the product (by name or length).
  - It does not take "4-6 personen", "een tour van 2 uur" or a greeting ("goedemiddag") for a day or a time.
- **"Nieuwe boeking"** (`QuickBooking.tsx`) has a box "Bericht van de gast" on top:
  - typing or pasting fills the form; "Plak van klembord" does it in one tap;
  - a line says what was filled in and what was not found (day, start time, number of guests);
  - the channel goes to Instagram unless the message holds a phone number or an e-mail address;
  - a second message resets the fields the first one filled, unless the founder changed them by hand, so one guest's name never stays on the next booking;
  - the message itself is not stored.
- **"Kopieer vragen voor de gast"** copies a short list of questions (`DM_QUESTIONS`). An answer in that shape is read completely.

## Decisions
- **No Instagram API.** Reading DMs automatically needs a Meta business app, an app review and a server that receives webhooks. That breaks the zero-cost and static-hosting rules, and it would put guests' messages on a server.
- **No share target.** Instagram only offers "Copy" on a message, so the clipboard is the shortest road.
- **Only wish sentences go to the notes,** not the whole message: store the minimum of personal data.

## Review findings (reported, not changed)

1. **Guide mode has no screen wake lock.** The phone screen goes dark while walking, and GPS updates then stop. `navigator.wakeLock` is free.

7. **`Agenda.tsx` is 718 lines** with the agenda, the departure page, the booking form and the product page in one file.
8. **No linter.** TypeScript is strict, which catches most, but not unused CSS or hook dependency mistakes.

## Later: a test that failed now and then
- **What happened:** before the push of `3fdf7fe` one store test failed locally ("leaves no personal data in a deleted booking"). The commit command did not stop on it, so the push went out anyway. The deploy run passed, because the test only fails now and then.
- **Cause:** sync tells an edit from "unchanged" by `updatedAt` alone. The test deleted a booking through an older copy of the record, in the same millisecond as the last save, so the tombstone got the same `updatedAt` as the stored version and the sync threw the delete away. In real use a save, a full sync and a second edit do not fit in one millisecond, but the rule was fragile.
- **Fix:**
  - `touch` (factory.ts) always moves `updatedAt` forward, also within one millisecond or with the clock set back;
  - `saveRecord` (store.ts) starts from the stored version's `updatedAt` when the caller holds an older copy.
- **Checks:** a new test for `touch`; the whole suite ran 25 times in a row without a failure (before the fix 5 of 12 runs failed). `npm test`: 195 passed.
